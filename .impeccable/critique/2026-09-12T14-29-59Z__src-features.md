## Design Specificity Verdict

The visual language is authored. The interaction model is not. And the differentiator is the weakest-designed thing in the app.

Specific to Splyt: the three-zone shell, rationed forest green, the event-icon vocabulary (palm tree for a Boracay weekend is a trip app, not a finance app), MAX_RECEIPTS=3 camera flow.

Generic: the entire interaction model. Four-icon shortcut row indistinguishable from a fitness app. BalanceScreens is a map with name-left/value-right. No quick-add, no repeat-last-expense, no swipe action, nothing in the thumb zone.

The central fund is expressed in one place (DashboardFundOverviewCard, which is excellent) and abandoned where it matters: in AddExpenseScreen selecting "Central fund" changes nothing, the Payer card still demands a human payer, the fund balance is never shown, and overspending is silent. The settlement summary never mentions the fund at all.

Anti-reference check: not dense, but the balances list and contribution list are Splitwise rows with a card drawn around each one. Padding is not hierarchy.

**Deterministic scan.** `impeccable detect --json` exited 0 on both paths with 3 advisory findings, all rule `design-system-color`: `#8E99A4` at EventScreenStyles.ts:175, :234, EventsScreen.tsx:211. No false positives. The detector under-reported: grep found 25 distinct non-token hex values across 20 sites and returned [] for src/components/ui despite `#C9CDD2` living there.

Measured evidence:
- Contrast: 6 of 13 token pairs fail 4.5:1; 3 fail even 3:1. White on #22C55E = 2.28. White on #F59E0B = 2.15. White on #4CAF50 = 2.78. #E74C3C error text on white = 3.82 at 12pt. #3B82F6 on white = 3.68. Neutrals all pass (inkMuted on white = 5.31).
- Touch targets: 8 interactive styles below 44pt, down to 28x28 (receiptRemoveButton). hitSlop occurrences: 0.
- Dynamic Type: no maxFontSizeMultiplier anywhere; 9 fixed-height containers wrapping scaling text.
- Destructive guards: 1 of 10. Alert.alert in src/features: 0.

**Visual overlays: not available.** React Native target, no web build, no browser-renderable dev server. Browser visualization skipped by design. Fallback signal: static measurement of StyleSheet.create blocks, token file, and JSX props.

## Overall Impression

The system is better than the product. A disciplined token layer and a good shell, then it stops before the screens that carry the money. The app looks trustworthy and behaves carelessly: a debt renders in the same green as a credit, at the smallest type size, in a color unreadable outdoors; it asks who paid for something the pool paid for; and it ends the group's trip on a static list with no way to say "done."

Biggest opportunity: the central fund. It is why the product exists, it already has one beautiful component proving the team can design it, and it is absent from the two screens where it would win the comparison — Add Expense and Settlement.

## What's Working

1. **DashboardFundOverviewCard is the design thesis, correctly executed.** 34pt available balance, two-segment spent/available track, contributed/spent labeled beneath. Answers "can we still put this on the pool?" with no arithmetic.
2. **The token layer makes drift visible.** Fixed 8pt spacing scale, 8-step type ramp with no orphan sizes, system fonts, #1C1C1E instead of #000.
3. **Deterministic avatar identity.** AppAvatar hashes a name to a stable color from an 8-pair palette; each pairing ships its own dark ink, so it survives without being color-only.

## Priority Issues

### [P0] The Android hardware back button does nothing, and the navigation stack is volatile
navigation.tsx keeps the stack in useState and never registers BackHandler. Back from Add Expense either does nothing or exits the app, discarding an in-progress expense including receipt photos. Process death has the same effect. Blocks task completion and loses data.
Fix: register BackHandler in AppNavigator calling goBack() and returning true while stack.length > 1, false at root. Unsaved-changes confirm on leaving Add Expense. Longer term, React Navigation native stack for the iOS edge-swipe.
Suggested command: $impeccable harden

### [P0] Money is the wrong size and the wrong color on the screens that exist to show money
Net balance renders inside a 12pt DataPill, the smallest text on a card whose member name is 17pt/600 — violating the system's own Money Is The Headline rule. `tone={balance.net >= 0 ? 'accent' : 'default'}` paints a debt green-on-green. Status/amount colors measure 2.15–2.78:1.
Fix: typography.amount plus a sign-bearing prefix ("You owe" / "You're owed"). Plain text instead of a pill: darkened red for debts, #2F6F57 for credits, both >=4.5:1. Darken every #4CAF50/#22C55E/#F59E0B text usage; reserve #22C55E for fills with ink-dark text.
Suggested command: $impeccable colorize then $impeccable audit

### [P1] Choosing "Central fund" changes nothing about the screen
Selecting Central fund leaves the Payer card visible, still labeled "Paid for this expense," still required, still submitted. Fund balance never appears; overspending is silent until settlement. Users mis-attribute the expense or conclude the feature is broken.
Fix: when paymentSource === 'central_fund', replace the Payer card with `Central fund · ₱X available`, live-preview the remaining balance, inline warning when amount exceeds it. Promote the source choice above Title.
Suggested command: $impeccable shape

### [P1] The accessibility floor is below the platform minimum
SelectableRow has no accessibilityState={{selected}} — a screen-reader user cannot determine who is in the split. Same in the icon picker and tab bar. 8 interactive styles below 44pt (down to 28x28), zero hitSlop. 9 fixed-height containers wrap scaling text with no maxFontSizeMultiplier. AppModal lacks accessibilityViewIsModal. Both modal backdrops are focusable and unlabeled.
Fix: accessibilityState on every selectable row/tab/tile; raise icon buttons to 44 or add hitSlop; accessibilityViewIsModal on AppModal and importantForAccessibility="no-hide-descendants" on backdrops; minHeight instead of height on text containers; cap maxFontSizeMultiplier ~1.6 on buttons and tab labels.
Suggested command: $impeccable audit

### [P1] The core loop has no ending
SettlementScreen lists "Suggested transfer" rows and stops. No mark-as-paid, no share, no completion state. The peak-end rule says the last moment defines the memory; the argument moves back into the group chat. Deleting an event gets a careful confirm modal while recording ₱5,000 gets silence.
Fix: a Share summary action producing plain text for the group chat, a genuine settled state when instructions.length === 0 that reads as an achievement, and one line attributing how much of the trip the central fund absorbed.
Suggested command: $impeccable onboard

## Persona Red Flags

**Jordan (confused first-timer)** — First event shows ₱0.00 as the largest number under "Available balance," a feature nothing explained. The events list labels the brand-new empty trip "Settled," read literally as nothing to do. `Currency: PHP` gives no clue whether it states or changes the value; one tap silently moves the trip to USD. Typing `1.200` on a QWERTY keyboard yields ₱1.20, saved silently. The screen pops back with no success message, so Jordan taps Save again and duplicates the expense.

**Sam (screen reader, Dynamic Type, 4.5:1)** — Cannot tell who is included in a split; SelectableRow never announces selected state. The invite-code control has no accessibilityLabel and never says "copy." Balance sign is pill-tone only. Error text is #E74C3C at 12pt (3.82:1) with no accessibilityLiveRegion and no field association. Unread count renders at 9pt. At Larger Accessibility Sizes, button labels clip inside fixed 48pt boxes and 11pt tab labels overflow the 64pt bar.

**Riley (stress tester)** — 200 members renders all 200 SelectableRows inline with no virtualization, no search, no select-all/none, all pre-selected: 198 taps to split a coffee between two people. Long event names wrap and break the events-list alignment while the dashboard clamps the same data. Emoji display names hit `parts[0].slice(0, 2)` and split a surrogate pair. PHP + USD events sum into one meaningless Home number. No RefreshControl anywhere — stale balances cannot be refreshed; the only recourse is force-quit.

## Minor Observations

- Five controls that look interactive and are not (Events-tab bell is `onPress={() => undefined}`; four SettingsRow entries render a chevron with no handler). Individually P2, collectively P1.
- The auth screen cannot scroll: AuthScreen uses a bare SafeAreaView > View, and AppScreen's `variant="auth"` branch (which has the KeyboardAvoidingView + ScrollView) is dead code. The keyboard covers the Create-account button.
- HomeEventCard already contains a `currentBalance` branch rendering "You're owed / You owe" that no caller ever passes.
- A dangling separator ships on screen: `${contributed} contributed · ` with nothing after the middot.
- Settings hardcodes DataPill label="Trusted" on every profile — a fabricated status.
- The signup placeholder says "At least 8 characters" while the schema enforces 6.
- Clipboard is imported from react-native core, from which it was removed.
- useSafeAreaInsets and SafeAreaProvider: 0 occurrences. tabBarBottomInset defaults to 0 and no caller computes it.
- No haptics anywhere, in a system whose stated character is "tactile and confident."

## Questions to Consider

1. If the central fund is the product, why is "add expense" the default action and "contribute to the fund" three taps deep? What if the dashboard's primary action were "Spend from the fund — ₱4,200 left"?
2. Splits are equal-only today — so why does the user tap through a participant list at all? What if Add Expense collapsed to "₱1,200 · everyone · from the fund" with participants as an editable chip?
3. You have a beautiful 38pt invite code that nobody can share without leaving the app. What happens when the invite becomes a deep link plus a native share sheet?
4. What would this app look like if it were designed for the thumb of someone standing up, holding a drink?
